    1. Letters name the axes
    
        
    A matrix A has two axes. Writing ij just gives them names: i for rows, j for columns, so an entry is A[i, j]. The letters themselves don't matter; ab or xy would mean the same thing.
    
        
    After the arrow -> you write which axes the result has, in which order. ij->ij changes nothing. ij->ji swaps the order, so the result is the transpose: out[j, i] = A[i, j].
    
        
     
    
      
    

      
    
        
    2. Leave a letter out to add it up
    
        
    A letter that's in an input but not in the output is summed over. ij->i keeps i and drops j, so each row is added up: one number per row. ij->j adds up each column. ij-> (nothing after the arrow) adds up everything into one number.
    
        
      
    
      
    

      
    
        
    3. Share a letter to multiply along it
    
        
    With two inputs, the entries are multiplied. A letter in both inputs lines them up: i,i->i multiplies A[0]·B[0], A[1]·B[1] and so on, element by element.
    
        
    Now combine it with rule 2: in i,i->, i is shared and missing from the output, so the products are added up. That's the dot product.
    
        
    With no shared letter, every entry meets every other: i,j->ij is the outer product, out[i, j] = A[i]·B[j].
    
        
      
    
      
    

      
    
        
    4. Matrix multiplication
    
        
    ij,jk->ik: j is shared, so A[i, j] and B[j, k] are multiplied for matching j; j is missing from the output, so those products are added up. That is exactly the definition of A @ B: row i of A against column k of B.
    
        
    Because you name the axes, you never have to transpose first: ij,kj->ik is A @ B.T, and ji,jk->ik is A.T @ B.
    
        
     
    
      
    

      
    
        
    5. Batch letters
    
        
    A letter that's in every input and the output is paired up but not added: each value of it gets its own result. In bij,bjk->bik, b is the batch, so this is one matrix multiplication per batch entry (like torch.bmm).
    
        
    Drop b from the output, bij,bjk->ik, and the batch results are added together instead.
    
        
     
    
      
    

      
    
        
    6. Four, five, six letters: sort them, don't read them
    
        
    Long equations are hard because you try to read them left to right. Instead, ask each letter two questions: is it in one input or both? and is it in the output? The answers put every letter in one of four groups, and the groups say everything:
    
        
    
          
    
            
    The letter is…GroupWhat happens
    
            
              
    in both inputs and the outputbatchpaired up; each value gets its own separate result
    
              
    in one input and the outputrows (from A) or columns (from B)carried through to the output
    
              
    in both inputs, not the outputcontractedmultiplied along, then added up
    
              
    in one input, not the outputsummedadded up inside that input first
    
                
          
    
        
    
        
    Then the whole equation is one batched matrix multiplication: for each batch value, (rows × contracted) @ (contracted × columns). It doesn't matter how many letters a group has; several letters in one group act like one long axis. The output is then just its letters in the order written after the arrow.
    
        
    Take abcd,cdef->abef. c and d are in both inputs but not the output: contracted. a, b come only from A: rows. e, f only from B: columns. So it's a (a·b) × (c·d) matrix times a (c·d) × (e·f) matrix. That's np.tensordot(A, B, axes=2).
    
        
    A habit that helps with real code: write each input's shape under its letters (b h q d over 32 8 128 64), check that every letter has one size everywhere, then sort the letters. For any two-input equation, the explorer shows this sorting under the formula, plus the same computation written with transpose, reshape and @.
    
        
     
    
      
    

      
    
        
    7. Worked example: attention
    
        
    In a transformer, queries and keys have shape (batch, heads, tokens, features). Name them b h q d and b h k d: q and k are both tokens, but they get different letters because they're separate axes of the result.
    
        
      
          
    • bhqd,bhkd->bhqk gives the attention scores. b, h: batch. q: rows (only in Q). k: columns (only in K). d: contracted. So for every batch and head, Q (q × d) @ Kᵀ (d × k). No transpose needed: the letters already say which axis lines up with which.
      • 
          
    • bhqk,bhkd->bhqd applies the weights to the values. Now k is the contracted letter, and d comes only from V.
      • 
          
    • bhqd->bqhd just moves the heads axis next to the features, ready to merge the heads with a reshape.
      • 
        
    
        
    A common mistake is using the same letter for both token axes: bhtd,bhtd->bhtt is an error (a letter can't appear twice in the output), and bhtd,bhtd->bht pairs each token only with itself. If two axes have the same size but play different parts, give them different letters.
    
        
      
    
      
    

      
    
        
    8. Three or more inputs
    
        
    With more inputs, every product still multiplies one entry from each input, and the same rules decide what's kept and what's added. To understand one, combine the inputs two at a time: ij,jk,kl->il is ij,jk->ik (j used up), then ik,kl->il (k used up). A letter can be added up as soon as no remaining input uses it.
    
        
    The order you pick changes the speed, not the answer; that's what optimize=True in NumPy is for.
    
        
     
    
      
    

      
    
        
    9. The same letter twice in one input
    
        
    ii means “row and column are the same”, so only the diagonal entries A[0, 0], A[1, 1]… are used. The matrix must be square. ii->i takes the diagonal; ii-> adds it up, which is the trace.
    
        
     
    
      
    

      
    
        
    10. Leaving out the arrow (and why not to)
    
        
    Without ->, the output is the letters that appear exactly once, in alphabetical order. So ij,jk means ij,jk->ik.
    
        
    The catch: ji on its own becomes ji->ij, which transposes, even though it looks like it shouldn't change anything. Writing the arrow every time avoids surprises.
    
        
     
    
      
    

      
    
        
    11. “...” for any number of leading axes
    
        
    ...ij,...jk->...ik means “matrix-multiply the last two axes, and treat everything before them as batch axes”, however many there are. Those batch axes broadcast like they do with @. The explorer above can't draw “...” (it could be any number of axes), but the Tensor Shape Visualizer works out the shapes it gives in real code.
    
      
    

      
    
        
    12. In NumPy and PyTorch
    
        
      
          
    • np.einsum("ij,jk->ik", A, B) and torch.einsum("ij,jk->ik", A, B) use the same notation.
      • 
          
    • One comma-separated term per input, in order, and one letter per axis of that input.
      • 
          
    • A letter means the same size everywhere it appears; if j is 3 in A, it must be 3 in B too.
      • 
          
    • With three or more inputs, the order in which pairs are multiplied can change the speed a lot. NumPy picks a good order with optimize=True; PyTorch does it when the opt_einsum package is installed.
